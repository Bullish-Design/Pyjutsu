## Race sweep

Test: `test_race_with_a_jj_cli_writer_ends_in_a_legal_outcome` (48 cases per run: 12 offsets, 2
writer kinds, colocated and plain). Two full runs, then repeated runs at one offset.

| Run | Outcomes |
| --- | --- |
| full run 1 | colocated: 17 published, 6 rejected, 1 published-late-fork; plain: 16 published, 8 rejected |
| full run 2 | colocated: 16 published, 8 rejected; plain: 16 published, 8 rejected |
| offset -30 ms, `jj new`, colocated, 15 runs | 14 published-late-fork, 1 rejected |

No run ended in a stale working copy, lost competitor bytes, or an exit code other than 0 and 1.
Every run ended with one operation head after the next jj command, `@` stable across a second
command, `@` a descendant of `onto` on success, and Git `HEAD` equal to `@-` in colocated repos.

**Finding that differs from the prototype.** The prototype swept plain repositories only and saw
no late fork. In a colocated repository a CLI `jj new` takes the Git lock again before it
publishes. The guard holds that lock. A `jj new` that had already loaded the old head waits, then
publishes on it and forks the log. The guard cannot prevent that. It can drop the Git lock, but
then a CLI writer that starts after the guard imports a half-synchronized Git `HEAD` as a new
operation. That was measured with a temporary switch (since removed): at +30 ms, 6 of 10 runs
failed the end-state check without the lock; 0 of 10 with it. The guard keeps the lock.

Negative control (`test_negative_control_without_the_comparison_a_third_outcome_appears`): with the
head comparison removed through the test-only switch, the deterministic race leaves two operation
heads. With the comparison, the same race gives `op-heads-moved` and one head.

## Operation counts

Colocated happy path: 2 operations (`publish smoke`, then `sync colocated git`). The second exists
because jj's view records Git `HEAD`, and the guard keeps "compare, publish, then sync" so a
rejected call never moves Git. Onto-the-current-parent: 1 operation (`git_sync=unchanged`). Plain
repository: 1 operation.

   after a shell entry. The build installs the executable.

5. `publish_if` fires no hooks (`pre-commit` and similar).
